# Ниша/Голос/Направления — редактируемые Владельцем через бота

Отменяет пункт ADR-0006 «Ниша сейчас одна, без UI для редактирования». Ниша, Голос и Направления (затравочный список для Wordstat-подбора Тем) были захардкожены как строковые литералы в промпт-коде (без фактического дублирования между собой — см. ниже); теперь каждый — единое значение в общей таблице `owner_settings(key, value, updated_at)` (не три отдельные таблицы вида `schedule_settings` — параметры структурно идентичны: одна строка/список на параметр, get/set, без версий и подтверждений, так что общая таблица не дублирует бойлерплейт трижды без выигрыша). Отсутствие строки трактуется как «нет переопределения»: `get()` возвращает `None`, и вызывающий код сам подставляет текущий хардкод как дефолт — тот же паттерн, что уже использует `schedule_settings`, без миграции-сида при выкатке.

Ниша и Голос текстуально независимы (Ниша фигурирует только в промптах подбора/регенерации Темы, Голос — только в промптах аутлайна/черновика Статьи; пересечения между ними, вопреки первоначальному предположению из триажа, в коде не было). Направления влияют только на Wordstat-поиск растущих запросов внутри `generate_plan`, не на текст промптов.

Голос дополнительно поддерживает заранее заготовленные шаблоны (хардкод-список пар «заголовок, текст» в командном слое бота, не в пайплайне) — выбор шаблона вызывает тот же `set`, что и ручной ввод текста, поэтому промпт-код Статьи не отличает и не должен отличать шаблонное значение от введённого вручную. Управление списком шаблонов через бота — вне рамок: это отдельная редактируемая сущность, целесообразная только при реальном запросе.
