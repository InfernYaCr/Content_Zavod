# Темы из Карты Ниши: каскад поводов вместо Направлений

Дополняет ADR-0006 и ADR-0008. Исследование и решения Владельца проекта — `docs/research/2026-10-12-weekly-topic-sourcing.md`, живые проверки API — `docs/research/2026-10-12-niche-map-live-checks.md`, задача #128.

Раньше `generate_plan` брал Направления Пространства (seed-запросы, которые писал Владелец), смотрел месячный рост в Wordstat и по каждому растущему писал Тему. Нетехнический Владелец не знает, какие запросы растут; месячный рост в основном сезонность; если ничего не растёт или Wordstat недоступен — пустой План или упавшая Задача.

## Решение

- **Направлений нет.** Бот сам строит **Карту Ниши** — до 30 запросов по Нише и Аудитории: один вызов модели (Ниша и Аудитория только как INPUT_DATA), спрос каждого запроса и похожие запросы из `GetTop`, частые вопросы из `GetTop` по «как <запрос>». Хранится JSON-значением `niche_map` в `workspace_settings` своего Пространства (отдельной таблицы нет). Перестраивается при смене Ниши или Аудитории и раз в 28 дней (через 7 дней, если Wordstat при постройке не ответил).
- **В Плане всегда 3 Темы.** Каскад: 6 запросов Карты по ротации (сначала давно не проверенные; запрос, давший Тему, «остывает» 4 недели) → недельная динамика (`GetDynamics PERIOD_WEEKLY` за 62 недели одним запросом): рост сверх сезона или начало сезона → новости Ниши за 2 недели (один веб-поиск «<запрос> новости», `period: PERIOD_2_WEEKS`) → даты на 3 недели вперёд из списка в коде → частые вопросы из Карты. Один вызов модели — «редактор Плана» — выбирает из кандидатов 3 Темы; если кандидатов мало, пишет вечные Темы.
- **Повод Темы** («почему сейчас») — строка под Темой, числа подставляет код. Хранится в `plan_items.why`; при Перегенерации Темы сбрасывается — новую Тему выбрали не по этому поводу.
- **Антиповтор:** «остывание» запроса + заголовки Тем Пространства за 180 дней в промпте редактора + отсев в коде по совпадению основ слов (доля общих основ ≥ 0,75); отсеянное редактор дописывает повторным вызовом (не больше 3 вызовов). Если Тем всё равно меньше 3 (модель ответила меньше или не в формате), План добирается без новых вызовов: сначала почти-повторы, затем сами кандидаты как Темы (вопрос, растущий или сезонный запрос, обычный запрос, дата), затем вечные шаблоны по Нише («<Ниша>: с чего начать», «…: частые ошибки», «…: как выбрать»), без повторов. Один кандидат даёт одну Тему: второй `Source` с тем же номером считается вечной Темой. Задача падает, только если пуста сама Ниша. Если модель вернула Карту без запросов, устаревшая Карта той же Ниши и Аудитории сохраняется с сегодняшней датой, а не заменяется пустой.
- **Wordstat и поиск не роняют План.** 429 Wordstat ждётся и повторяется в клиенте (2 и 4 с), затем Wordstat для этой Задачи выключается; на весь Wordstat у Задачи 120 с. Ошибка, 429 или XML-ошибка 32/55 веб-поиска — «новостей нет». Падает Задача только когда не ответила модель.
- **Кэш** недельной динамики и новостей — в памяти воркера по (фраза, неделя), общий для Пространств: это публичная статистика Яндекса, и чужая фраза никому не показывается. Карта — только своего Пространства.

## Отвергнуто

- Эмбеддинги для антиповтора: нужен ещё клиент и хранение векторов; совпадение основ плюс история в промпте дешевле. Вернуться, если повторы по смыслу всё же проходят (#79).
- `GetTop` каждую неделю ради вопросов: вопросы меняются медленно, они берутся из Карты (раз в месяц).
- Заголовок новости в строке Повода: в свежих новостях встречается мат (живая проверка). Показывается только домен источника.
- «Популярное» VC.ru и Дзена, Google Trends — условия площадок и доступ (решение Владельца).

## Цена

Обычный План: 6 запросов Wordstat (0,12 ₽) + 1 веб-поиск (0,49 ₽ днём) + 1 вызов редактора (~2 тыс. токенов, ~1,6 ₽) ≈ 2,2 ₽. Карта раз в 4 недели: 1 вызов модели (~0,6 ₽) + до 12 запросов Wordstat (0,24 ₽) ≈ 0,2 ₽ на План. Итого ≈ 2,4 ₽ за План; повторный вызов редактора при повторах — до +1,6 ₽.
