## Локальный запуск

1. `cp .env.example .env` и заполнить: `TELEGRAM_BOT_TOKEN` (отдельный тестовый бот), `TELEGRAM_NOTIFY_CHAT_ID` (группа команды, бот в ней), `POSTGRES_DSN`, `YANDEX_FOLDER_ID` и один из `YANDEX_API_KEY` / `YANDEX_OAUTH_TOKEN`. Для учёта стоимости — `YANDEX_TEXT_COST_PER_1K_TOKENS`, `YANDEX_IMAGE_COST_PER_GENERATION`, `YANDEX_SEARCH_COST_PER_REQUEST`.
2. Postgres: `docker run -d -p 5432:5432 -e POSTGRES_PASSWORD=postgres postgres:16-alpine`.
3. Два процесса: `uv run python bot_main.py` и `uv run python worker_main.py`. Миграции применяются при старте.
4. Зарегистрировать себя Владельцем — README, «Локальный запуск», шаг 4.
5. Тесты: `uv run --frozen pytest` (нужен Docker), `uv run --frozen ruff check .`, `uv run --frozen ruff format --check .`.

Сервисному аккаунту Yandex Cloud нужны роли на YandexGPT, YandexART и Search API (web search и Wordstat).

## Чек-лист приёмки (#19)

Проверять глазами пользователя, с телефона, в личке и в группе.

**Первый запуск**
- [ ] Описание бота видно до `/start`.
- [ ] `/start` Владельца в личке запускает Онбординг: Ниша → Аудитория → Персона → Направления (кнопка «✨ Предложить по Нише») → Проект → «Проверьте вводные» → 🚀.
- [ ] Первый План приходит в чат команды. Засечь время: в тексте бота обещано «обычно 2–5 минут».
- [ ] В чате команды закреплено «📌 Как мы работаем» (боту нужны права на закреп).

**Интеграции — главные риски**
- [ ] **Yandex Search.** Поле `region: "225"` в запросе (`yandex/web_search.py`) взято из схемы API и вживую не проверено. Если API его отвергает, у всех Статей будет «⚠️ Поиск источников был недоступен». Проверить `research_status` у Версии и шаг `research_search` в `generation_steps`.
- [ ] **Telegraph.** Страница открывается в Instant View, после «✏️ Доработать» URL тот же, «📖 Читать» остаётся после ✅.
- [ ] **Wordstat.** «✨ Предложить по Нише» для не-маркетинговой Ниши даёт осмысленные запросы. Порог спроса — `MIN_FREQUENCY` = 100/мес.
- [ ] **ForceReply в группе** открывает ответ только у нажавшего (упоминание `tg://user`).

**Неделя работы**
- [ ] План: 🔄 и 🗑 по Темам, «Утвердить всё». После утверждения сообщение становится Хабом, прогресс обновляется в нём же, лишних сообщений нет.
- [ ] Хаб: кнопка Темы → карточка результата → «◀ К Плану». Обложка и карточки Статей приходят по нажатию.
- [ ] Карточка Статьи: превью, «📖 Читать», «✏️ Доработать», «⬇️ .docx/.md», «✅». В .docx и .md нет служебных пометок.
- [ ] Удалить сообщение Плана руками → следующее обновление присылает новое.

**Меню, Настройки, Инструкция**
- [ ] `/menu`, Экран Настроек, изменение каждой Настройки, «-» очищает Проект и Аудиторию.
- [ ] «📖 Как пользоваться»: слайды листаются, картинки читаются на телефоне; у Контент-менеджера 5 слайдов.

## Как разбирать качество Статей

Для каждой Статьи:
- **Факты.** Каждая цифра и утверждение с `[N]` подтверждается своим источником. Открыть источник и сверить цитату. Это ещё не проверяет код, только наличие evidence (E3 в `docs/plans/2026-08-12-technical-hardening-and-saas.md`).
- **Читаемость.** Связный текст, не список фактов; сноски не слишком частые (особенно на Дзене); нет «evidence», `[E1]`, английских слов.
- **Площадка и Персона.** Объём в пределах целевого (Дзен 4000–6000, VC.ru 6000–9000 знаков), тон Персоны, текст для Аудитории.
- **Проект.** Ровно один CTA со ссылкой, в конце, естественно.
- **Темы.** Подходят Нише и Аудитории, не повторяются (#79).

Найденное — issues с примерами из Статей, правки промптов — с поднятием версии в `_PROMPT_VERSIONS`.
