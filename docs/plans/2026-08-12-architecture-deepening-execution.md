# Раскладка исполнения: углубление модулей

Как запускать шесть кандидатов из обзора архитектуры параллельными агентами.

Источник кандидатов — `docs/reviews/architecture-review-2026-08-12.html`. Там для
каждого лежат `file:line`, диаграммы «до/после» и обоснование. Этот документ не
повторяет их, а отвечает на другой вопрос: **в каком порядке и в какой изоляции
их исполнять**.

## Статус

Кандидат 01 отгрилен, спека и тикеты созданы. Остальные пять ждут своего
`/grill-with-docs` → `/to-spec` → `/to-tickets` — каждый в одном непрерывном окне.

Нумерация 01–06 ниже — это **номера кандидатов из обзора**, не номера GitHub
issue.

| Кандидат | Название | GitHub issue |
|---|---|---|
| 01 | Настройки Владельца | #48 (срезы: #49–#53) |
| 02 | Контракт Задачи | — |
| 03 | Кодек callback-данных | — |
| 04 | Диспетчер callback'ов | — |
| 05 | Ролевой гейт | — |
| 06 | Одна фикстура Postgres | — |

Решения грилинга по 01 зафиксированы в ADR-0009 (Голос переименован в Персону,
ключ в БД сохранён) и ADR-0010 (кастомная Персона структурирована и попадает в
system-промпт).

### Внутри кандидата 01 параллельности нет

GitHub снимает блокировку с #50, #51 и #52 одновременно — после закрытия #49 у
каждого остаётся ноль открытых блокеров. Это **не** значит, что их можно вести
параллельно: все три правят один модуль Настройки, командный слой бота и сборку
промптов. Здесь блокирующие рёбра описывают порядок решений, а не изоляцию
файлов.

Вести последовательной цепочкой в одном чате, с `/clear` между тикетами:

```
#49 → #50 → #51 → #52 → #53
```

Worktree для кандидата 01 не нужен. Он понадобится на волне 1 (кандидаты 01 ∥ 03),
когда у 03 появятся свои тикеты.

## Принцип раскладки

Логическое ребро «05 блокирует 04» — не единственное ограничение. Второе, более
жёсткое: **какие файлы правит каждый кандидат**. Два агента в одной рабочей
директории пишут поверх друг друга независимо от того, что говорят блокирующие
рёбра.

| Кандидат | Ключевые файлы | Конфликтует с |
|---|---|---|
| 01 Настройки | `owner_settings/`, `telegram/*_command.py`, `pipelines/` | 02 |
| 03 Кодек | `telegram/gateway.py`, `telegram/__init__.py`, `bot.py` | 04, 05, 02 |
| 06 Фикстуры | `tests/*/conftest.py` | — |
| 05 Ролевой гейт | `bot.py`, `access/` | 03, 04, 02 |
| 04 Диспетчер | `bot.py`, `telegram/` | 03, 05, 02 |
| 02 Контракт Задачи | `domain/`, `pipelines/`, `worker.py`, `bot.py` | все |

`entrypoints/bot.py` — точка сборки четырёх кандидатов. Параллелить их в одной
директории нельзя.

## Волны

### Волна 0 — соло: 06 Фикстуры

Идёт первой, одна. Меняет тестовую инфраструктуру, на которую лягут тесты всех
остальных кандидатов, — если сделать её позже, каждый следующий агент будет
разруливать конфликт в `conftest.py`. Работы примерно на час.

### Волна 1 — два агента параллельно: 01 ∥ 03

Файлы почти не пересекаются. Единственная точка касания —
`telegram/__init__.py`: 03 переписывает `__all__`, 01 может убрать оттуда пару
имён. Мержить 03 первым, 01 вторым.

### Волна 2 — один агент последовательно: 05 → 04

Оба живут в `bot.py`, и 04 логически ждёт 05. Разносить по чатам смысла нет:
изоляция ничего не даёт, а мерж двух веток в один файл даст конфликт.
Развилка по форме шва под aiogram решается один раз на оба.

### Волна 3 — после потока A: 02 Контракт Задачи

Заблокирован пунктами A2–A4 из `2026-08-12-technical-hardening-and-saas.md` —
они правят ровно те же места (lease/fencing, идемпотентность применения
результата, lifecycle ошибок Статьи). Проектировать контракт до того, как они
приземлятся, значит проектировать по устаревшему коду.

## Изоляция через worktree

Только для волны 1 — остальные волны последовательны и worktree не требуют.

```bash
git worktree add ../cz-settings -b arch/owner-settings
git worktree add ../cz-callback-codec -b arch/callback-codec
```

В Claude Code открыть по чату на каждый worktree, указав его рабочей
директорией. Агенты физически не могут задеть чужие файлы, каждый кандидат
приезжает своим PR, `/code-review` внутри `/implement` работает против чистого
диффа.

После мержа:

```bash
git worktree remove ../cz-settings
git worktree remove ../cz-callback-codec
```

## Практики контекста

- **Один тикет — один чат**, `/clear` между тикетами. Каждый тикет
  самодостаточен, контекст предыдущего выбрасывается.
- **Тело тикета несёт `file:line` и ссылку на отчёт.** Главный расход токенов —
  не чтение файлов, а повторная разведка: агент без точных координат начнёт
  обходить кодовую базу заново.
- **Smart zone ~150k.** Цепочку `/grill-with-docs` → `/to-spec` → `/to-tickets`
  рвать нельзя; если она подходит к границе — `/compact`, не новый чат.
  Для всего остального артефакт на диске лучше переноса контекста.
- **jcodemunch** — индекс репозитория, стартовая точка для поиска по коду
  (см. `CLAUDE.md`). Держать в актуальном состоянии: `incremental=true`.
- **Модель под задачу.** 06 механическая — хватит модели попроще. 01, 04 и 05
  проектные.
- **`uv run ruff check --fix` до коммита** — иначе pre-commit завернёт агента и
  он потратит ход на разбор.
