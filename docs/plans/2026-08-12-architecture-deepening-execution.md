# Раскладка исполнения: углубление модулей

Как запускать шесть кандидатов из обзора архитектуры параллельными агентами.

Источник кандидатов — `docs/reviews/architecture-review-2026-08-12.html`. Там для
каждого лежат `file:line`, диаграммы «до/после» и обоснование. Этот документ не
повторяет их, а отвечает на другой вопрос: **в каком порядке и в какой изоляции
их исполнять**.

## Статус

|---|---|---|---|
| 01 | Настройки Владельца | #48 (срезы #49–#53) | готов |
| 02 | Контракт Задачи | — | разблокирован, не заведён |

| 04 | Диспетчер callback'ов | #68 | готов |

Кандидат 01 прошёл полный маршрут `/grill-with-docs` → `/to-spec` →

system-промпт).

Кандидаты 06 и 03 заведены тикетом напрямую, без грилинга и спеки. У 06 решений
не было вовсе. У 03 единственная развилка — что кодек принимает на вход — была
записана в тело #61 открытым вопросом и решена по ходу реализации; результат в

названная в теле тикета, не потерялась и доехала до ADR.

Кандидаты 04 и 05 прошли общим грилингом (#66) — у них была одна развилка по
форме шва под aiogram, решённая один раз на оба. Результат: `CallbackInput` как
форма события без aiogram, `unpack_callback_query` единственной функцией-адаптером
и исчерпывающий `match` с `assert_never` в `callback_dispatcher.py`.
Шов настоящий, а не гипотетический: два адаптера — aiogram в проде, значения
руками в тестах.

**Кандидат 02 разблокирован.** Он ждал пунктов A2–A4 потока укрепления; они
закрыты этапом 1 (`1348d77`), а остаток A3 — тикетом #73. Тикета у 02 пока нет:

пунктов A6/A7/A8 — 02 про форму модулей, а те про риск для продукта.

### Уроки пройденных кандидатов

**Ставить `Closes #N` в теле PR.** PR #57, #60, #64 и #65 смержились, не закрыв
тикеты: GitHub реагирует на ключевое слово, а голая решётка в заголовке — просто
ссылка. Каждый раз тикет приходилось закрывать вручную, заново разбираясь, что
именно доехало. Три кандидата подряд — значит дело не в забывчивости, а в
шаблоне PR: стоит внести `Closes #` в `.github/pull_request_template.md`.

**Блокирующие рёбра описывают порядок решений, а не изоляцию файлов.** GitHub
снял блокировку с #50, #51 и #52 одновременно, хотя все три правили один модуль
Настройки, командный слой бота и сборку промптов. Вести их пришлось цепочкой
`#49 → #50 → #51 → #52 → #53` в одном чате, с `/clear` между тикетами. Перед
запуском параллельных агентов сверяться с таблицей файлов ниже, а не с рёбрами.

## Принцип раскладки

Логическое ребро «05 блокирует 04» — не единственное ограничение. Второе, более
жёсткое: **какие файлы правит каждый кандидат**. Два агента в одной рабочей
директории пишут поверх друг друга независимо от того, что говорят блокирующие
рёбра.

| Кандидат | Ключевые файлы | Конфликтует с |
|---|---|---|
| 02 Контракт Задачи | `domain/`, `pipelines/`, `worker.py`, `bot.py` | — |

Остался один кандидат, конфликтовать не с чем. Правило само по себе в силе и
пригодится на следующем обзоре.

## Изоляция через worktree

**Так и не понадобилась.** Кандидаты, которые можно было вести параллельно,
разошлись по времени: 01 и 03 делались подряд, а не одновременно. Все остальные
сходились на `entrypoints/bot.py` и шли последовательно, каждый обычной веткой
от master.

Держится здесь на случай, если появится пара действительно непересекающихся
кандидатов:

```bash
git worktree add ../cz-<кандидат> -b arch/<кандидат>
```

В Claude Code открыть по чату на каждый worktree, указав его рабочей
директорией. Агенты физически не могут задеть чужие файлы, каждый кандидат
приезжает своим PR, `/code-review` внутри `/implement` работает против чистого
диффа. После мержа — `git worktree remove`.

## Практики контекста

- **Один тикет — один чат**, `/clear` между тикетами. Каждый тикет
  самодостаточен, контекст предыдущего выбрасывается.
- **Тело тикета описывает поведение и критерии приёмки, а не файлы.** Соблазн
  вписать туда `file:line` ради экономии разведки надо давить: для рефакторинга
  на углубление это зафиксировало бы ровно ту структуру, которую и надо менять.
  Достаточно ссылки на обзор — координаты лежат там. Стоимость разведки
  закрывает индекс jcodemunch.
- **`Closes #N` в теле PR.** Без ключевого слова GitHub тикет не закроет, и
  через неделю никто не вспомнит, что из тикета реально доехало.
- **Smart zone ~150k.** Цепочку `/grill-with-docs` → `/to-spec` → `/to-tickets`
  рвать нельзя; если она подходит к границе — `/compact`, не новый чат.
  Для всего остального артефакт на диске лучше переноса контекста.
- **jcodemunch** — индекс репозитория, стартовая точка для поиска по коду
  (см. `CLAUDE.md`). Держать в актуальном состоянии: `incremental=true`.
- **Модель под задачу.** 06 механическая — хватит модели попроще. 01, 04 и 05
  проектные.
- **`uv run ruff check --fix` до коммита** — иначе pre-commit завернёт агента и
  он потратит ход на разбор.
