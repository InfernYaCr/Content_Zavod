# UX- и пайплайн-ревью Telegram-бота Content Zavod

**Дата:** 6 октября 2026 года
**Режим:** read-only анализ всего пайплайна, без опоры на текущие ADR и CONTEXT.md
**База анализа:** `master` на коммите `53f10e1` + незакоммиченные изменения рабочего дерева (миграции 0006/0007, прогресс генерации Плана). Номера строк — по рабочему дереву.
**Эталон UX:** бот «Постодел» (`@ai_author_nc_bot`), пройден вручную от `/start` до пейвола.

## Как путь выглядит сейчас

```
/start → «Добро пожаловать. /help» (или кнопка «Запросить доступ»)
Пн 09:00 или /generate_plan → Wordstat по Направлениям → 1 вызов LLM на растущий запрос → 3 Темы
→ сообщение Плана в чате команды: [🔄 Перегенерировать][❌ Удалить] × N, [✅ Утвердить всё]
→ по каждой Теме: обложка + (Дзен, VC) × 4 вызова LLM (outline → draft → rewrite → sources)
→ счётчик «🔄 Готовлю материалы 3/9» → в конце пачка: 6 карточек Статей + 3 обложки
→ карточка Статьи: [.docx][.md][🔄][✅][🖼]
```

## Эталон: путь в «Постоделе»

1. Карточка «что умеет бот» с картинкой ещё до `/start`, большая кнопка «Начать».
2. Развилка: «🔗 По каналу — точнее» / «✍️ Без канала — быстрее».
3. Ниша — текстом или голосом, с примерами и кнопкой «Назад».
4. Идеальный клиент — с примерами и объяснением, зачем это нужно.
5. Карточка «Проверь вводные» → [Начать анализ] [Назад].
6. «🔥 Подбираю идеи — около минуты» + параллельный «глубокий анализ».
7. Идеи по 4 на странице: кнопки 1–4, ← →, «Сгенерировать новые», «Своя идея».
8. После выбора клавиатура снимается, приходит чеклист этапов с ✅/⏳.
9. Готовый пост → «Готово!» → тарифы.

Что берём: пошаговый ввод с примерами и «Назад», карточку подтверждения, мгновенный первый результат, нумерованный выбор, «своя идея» рядом с подбором, живой чеклист этапов, минимум команд. Что не берём: пейвол, блокировку команд на время приветствия (у них `/main_menu` отвечает «недоступна»), голосовой ввод (нужен STT — позже).

## P0 — сломано или вводит в заблуждение

1. **Двойное нажатие 🔄 уничтожает сообщение Плана.** Второе нажатие той же кнопки трактуется как «Пропустить», и `edit_notice` перезаписывает *само сообщение Плана* на «⏳ Генерирую...» без клавиатуры (`telegram/callback_dispatcher.py:315`). То же с карточкой Статьи (`:287`).
2. **План не перерисовывается после действий.** Перегенерация Темы шлёт отдельное «Тема обновлена», а в Плане остаётся старый заголовок (`entrypoints/bot.py:459`). «Удалить» и «Утвердить всё» тоже не перерисовывают План.
3. **Кнопки Плана без номеров.** Все строки — одинаковые «🔄 Перегенерировать | ❌ Удалить» (`telegram/gateway.py:129`); статусы сырые: «Тема — pending_review» (`gateway.py:105`).
4. **`/topic` из лички «угоняет» План.** Если у Плана ещё нет сообщения, оно создаётся в чате вызова (`telegram/topic_command.py:69`), и дальше все обновления идут туда. Прогресс `approve_all` тоже уходит в чат нажатия, а Статьи — в `TELEGRAM_NOTIFY_CHAT_ID`.
5. **`/generate_plan` после упавшей генерации — no-op.** Тот же `idempotency_key` возвращает старую `failed`-задачу (`job_queue/queue.py:67`), а бот пишет «Генерирую План на 2026-W41...».
6. **Пустой План.** Нет растущих Направлений или Wordstat лежит — ошибки проглатываются (`pipelines/plan_pipeline.py:82`), создаётся План из одной кнопки «Утвердить всё», которая ничего не запускает.
7. **Комментарий к перегенерации Статьи теряется.** Его видит только outline; draft строится по заголовку+аутлайну (`pipelines/article_prompts.py:114`), rewrite — по черновику. Summary/keywords при перегенерации не передаются.
8. **✅ блокирует перегенерацию.** ✅ переводит Статью в `exported`, а перегенерировать можно только `ready`/`error` (`domain/article.py:33`). Обратной связи на ✅ нет.
9. **Все файлы — `article-zen.docx`.** Slug оставляет только `[a-z0-9]`, кириллица вырезается (`domain/export.py:18`).
10. **Ввод комментария.** Любое следующее сообщение пользователя в группе считается комментарием; ожидание в памяти, теряется при рестарте (`telegram/comment_gated_regeneration.py:31`). При privacy mode ответ не дойдёт до бота, без него бот отвечает «Доступ запрещён» на каждое сообщение не-участника (`entrypoints/bot.py:325`).
11. **Сырые ошибки.** «Задача generate_article завершилась ошибкой: <исключение>» (`entrypoints/bot.py:436`); алерты на английском (`Plan item '…' is not editable (status='approved')`).
12. **Доступ.** Каждое «Запросить доступ» — новая заявка, спам владельцам (`access/join_requests.py:45`); можно удалить себя/последнего Владельца (`access/membership.py:58`); `/members` показывает голые id; Контент-менеджер через `/generate_plan` может архивировать утверждённый План без предупреждения.

## P1 — качество контента

1. **Источники выдумывает LLM.** Шаг sources генерирует URL после написания текста (`pipelines/article_pipeline.py:248`), вопреки правилу промпта «не выдумывай ссылки». HTTP 200 ≠ подтверждение утверждения. Исследование уже описано в плане `docs/plans/2026-08-12-technical-hardening-and-saas.md` (research bundle).
2. **Тема не исследуется; каждая Площадка — с нуля.** 8 вызовов LLM на Тему, Дзен и VC могут противоречить друг другу в фактах. Лучше: общий research+outline на Тему → draft/rewrite на Площадку.
3. **Нет целевой длины и проверки обрезки.** `maxTokens` не задан, статус альтернативы не проверяется (`yandex/text_generator.py:114`) — обрезанная Статья сохранится как готовая.
4. **Подбор Тем.** Один растущий запрос → одна Тема без анализа выдачи; дедуп по точному заголовку; 3 Темы зашиты. Уже обсуждается в #79.

## P2 — UX/UI: что упростить

1. **Одно место работы:** всё командное — в групповом чате; в личке — меню и Настройки Владельца.
2. **План с drill-down:** нумерованные кнопки 1…N → карточка Темы в том же сообщении (описание, ключи, «✏️ Переписать», «🗑 Убрать», «◀ К Плану»); внизу «✅ Запустить: 3 Темы × 2 Площадки» и «🔄 Новый План». Перерисовка из БД после любого действия.
3. **Один живой хаб вместо пачки из 9 сообщений:** чеклист по Темам (обложка/Дзен/VC ✅⏳❌), по готовности — оглавление с карточками результата.
4. **Статью можно прочитать в Telegram:** превью ~800 символов + «Читать целиком»; кнопки «✏️ Доработать», «⬇️ .docx/.md», «✅ Готово».
5. **Надёжный ввод текста:** ForceReply, ожидание в БД, «Отмена» — общий механизм для комментариев, Настроек и онбординга.
6. **Меню вместо 14 команд:** `/start`, `/menu`, `/help`; Настройки, Расписание, Участники — экраны с кнопками.
7. **Человеческие тексты:** словарь статусов, «Дзен/VC.ru», даты вместо `2026-W41`, ошибки с «🔁 Повторить», технический текст — только в лог.
8. **Онбординг:** Владелец — визард Ниша → Персона → Направления → подтверждение → сразу первый План; Контент-менеджер — объяснение после одобрения.

## Упрощения в коде

- **Прогресс считать из БД, а не счётчиком.** Механика `generation_total/done` из незакоммиченной 0006 заменяется перечитыванием статусов Статей/обложек Плана на каждое уведомление. Пропадает класс багов двойного подсчёта (например, «Повторить» упавшей задачи внутри открытой пачки засчитает её дважды). Решить до коммита 0006.
- **Удалить мёртвый код** `_legacy_*` в `pipelines/article_pipeline.py:204`.
- **Схлопнуть команды Настроек** (`niche/directions/persona/schedule/settings_command`) в один экран.
- **Одна функция перерисовки Плана** вместо разных путей «notice/edit» в каждой ветке.
