Ключ, дефолт и нормализация уезжают внутрь реализации. Вызывающий код называет понятие, а не строковый ключ.

Проблема

Чтобы ответить «какая сейчас Ниша?», командный модуль Telegram импортирует NICHE_KEY и DEFAULT_NICHE из пайплайна сборки промптов.

Решение

Убрать ключ, дефолт и parse_directions за один интерфейс модуля owner_settings, названный по понятиям. И пайплайны, и команды зовут его.

Выигрыш

  • locality: одно определение Ниши
  • Минус 6 дублей протокола
  • Минус 5 рёбер telegram→pipelines
  • Интерфейс сжимается до понятий
  • Тесты подменяют один интерфейс
Задевает ADR-0008 — там сказано: «get() возвращает None, и вызывающий код сам подставляет текущий хардкод как дефолт». Стоит переоткрыть: этот дефолт сейчас подставляется в пяти местах, и settings_command лезет за ним сразу в два пайплайна. Сама общая таблица owner_settings(key, value) — предмет того ADR — не меняется.

2 · Схлопнуть скопированный ролевой гейт в точке входа бота

Уверенно внутри процесса
  • src/content_zavod/entrypoints/bot.py:181–353
  • src/content_zavod/telegram/commands.py

Было — 6 тонких слоёв, повторённых 13 раз

if message.from_user is None: return
role = await _role_for(...)
if role is None: return
if role != "owner":
    send_error(_OWNER_ONLY_TEXT); return
await handle_niche_command(...)
× 13 хендлеров ≈ 90 строк из 629

«Кому что можно» лежит в двух местах: меню в commands.py и гейт здесь.

Станет — гейт при регистрации, один толстый слой

модуль регистрации команд register(router, "niche", role="owner") from_user · поиск роли · проверка владельца · текст ошибки
await handle_niche_command(...)
13 хендлеров × 1 строка

Требуемая роль становится фактом в точке регистрации — оттуда же её может читать commands.py.

Проблема

Новая команда Владельца — это снова та же пятистрочная преамбула плюс не забыть добавить её в OWNER_COMMANDS. Забыть можно любое из двух, и в одну сторону это ломается молча.

Решение

Модуль регистрации с интерфейсом register(router, name, role, handler). Гейт становится реализацией, роль — данными, которые читает и меню команд.

Выигрыш

  • locality: одна проверка доступа
  • Меню и гейт делят один факт
  • leverage: 1 интерфейс, 16 хендлеров
  • Гейт становится тестируемым напрямую

Проблема

Каждая кнопка продукта проходит через одну цепочку из 110 строк, до которой можно добраться только собрав aiogram-объект CallbackQuery — поэтому она не покрыта тестами вовсе.

Решение

Выигрыш

  • 17 веток становятся достижимы
  • Действия только-для-Владельца в одной таблице
  • bot.py теряет ~110 строк

  • Навигация для ИИ: шов называет задачу

Главная рекомендация

1 · Углубить модуль настроек Владельца

Он лежит ровно на горячей точке — последние шесть коммитов трогали Нишу, Голос и Направления — и это единственный кандидат, который убирает утечку через шов, а не переставляет уже работающий код. Сейчас командный слой Telegram импортирует ключи хранения и дефолты для показа из пайплайнов сборки промптов. Углубите owner_settings — и оба вызывающих модуля получат интерфейс, названный по понятию предметной области, а не по строковому ключу; шесть дублей протокола исчезнут; а следующая настройка Владельца станет одним методом, а не пятью файлами.
